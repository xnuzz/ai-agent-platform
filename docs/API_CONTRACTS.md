# API Contracts — v1

Machine-readable contract: **`docs/openapi.yaml`** (generated by drf-spectacular; CI fails on drift). Live: `/api/docs/`.
This file defines conventions and the agent integration contract in prose. When the two disagree, fix the code or this doc in the same PR.

## Conventions
| Topic | Rule |
|---|---|
| Base path | `/api/v1/` — breaking changes require `/api/v2/` or a documented migration window |
| IDs | UUID v4 strings |
| Time | ISO 8601, UTC (`2026-11-08T14:00:00Z`) |
| Enums / statuses | `UPPER_SNAKE_CASE`, defined only in `backend/apps/common/enums.py` |
| Pagination | `?page=N&page_size=M` (default 25, max 100) → `{count, next, previous, results}` |
| Filtering / ordering | query params per endpoint (`?status=PENDING`, `?ordering=-score`) |
| Workspace scope | Header `X-Workspace-ID: <uuid>` on every workspace-scoped user endpoint. Missing/foreign → `400 workspace_required` |
| Idempotency | Agent result items carry `ref`; resubmission is safe |

### Errors (all endpoints)
```json
{"error": {"code": "invalid_state", "message": "Human readable", "details": {}}}
```
| HTTP | code | Meaning |
|---|---|---|
| 400 | `validation_error` | `details` = field errors (nested paths like `campaigns[0].messages[1].lead_ref`) |
| 400 | `workspace_required` | bad/missing `X-Workspace-ID` |
| 401 | `not_authenticated` / `authentication_failed` | |
| 403 | `permission_denied` | role too low, or wrong credential type |
| 404 | `not_found` | includes other workspaces' / other agents' objects |
| 409 | `invalid_state` | transition not allowed (see WORKFLOWS.md) |
| 409 | `conflict` | duplicate (e.g. approval already pending) |
| 409 | `stale_approval` | target changed after approval was requested |
| 409 | `compliance_blocked` | launch blocked; `details.reasons` = [`software_idea_not_approved`, `project_brief_not_approved`, `sender_identity_incomplete`] |
| 409 | `lease_lost` / `task_not_running` / `cancel_requested` | agent lease errors |
| 429 | `throttled` | auth/public endpoints |
| 500 | `server_error` | |

### Inbound email events (webhook)
Provider-neutral. A provider adapter or relay must translate SES/Mailgun/Postmark payloads to this format (**adapters not implemented**).
```
POST /api/v1/webhooks/email-events/
X-Webhook-Timestamp: <unix seconds>            # rejected if more than 300 s off (replay protection)
X-Webhook-Signature: sha256=<hex HMAC-SHA256(EMAIL_WEBHOOK_SECRET, "<timestamp>.<raw body>")>
{"events": [{"type": "BOUNCE|COMPLAINT|UNSUBSCRIBE|REPLY|DELIVERED", "email": "...", "message_id": "<Message-ID>",
             "bounce_type": "HARD|SOFT", "occurred_at": "..."}]}
→ 200 {"processed", "suppressed", "replies", "unmatched", "ignored"} · 401 bad/expired signature · 503 disabled
```
Matching: `message_id` = the `Message-ID` header we sent (stored as `OutreachMessage.provider_message_id`); else every sent message to `email`.
Effects: HARD `BOUNCE` → suppression `BOUNCE`; `COMPLAINT` → `COMPLAINT`; `UNSUBSCRIBE` → `OPT_OUT` (all source `SYSTEM`, idempotent); `REPLY` → lead `CONTACTED → REPLIED`; SOFT bounce and `DELIVERED` are ignored in v1.

## Agent API (`Authorization: Agent agt_<prefix>_<secret>`)
Use `agents/platform_sdk` — it implements all of this. Writes to a task require header **`X-Lease-Id`** = `lease_id` from the claim.

| Method & path | Body → Response |
|---|---|
| `POST agent/tasks/claim/` | `{worker_id, task_types?}` → `{task: AgentTask|null}` |
| `GET agent/tasks/{id}/` | → `AgentTask` |
| `POST agent/tasks/{id}/heartbeat/` | `{progress?: 0-100, stage?: str≤60, message?: str≤500}` → `{status, cancel_requested, lease_expires_at}` (renews lease) |
| `POST agent/tasks/{id}/results/` | Result Bundle → Result Report |
| `POST agent/tasks/{id}/complete/` | `{summary: {}}` → `AgentTask` (COMPLETED, or CANCELLED if cancel was requested) |
| `POST agent/tasks/{id}/fail/` | `{code, message?, retryable?}` → `AgentTask` (QUEUED if retryable & attempts left; CANCELLED if code=`CANCELLED`; else FAILED) |
| `POST agent/suppression/check/` | `{task_id, emails[], phones[]}` → `{suppressed_emails[], suppressed_phones[]}` |

`AgentTask` = `{id, workspace_id, agent, task_type, status, input, attempt, max_attempts, lease_id, lease_expires_at, cancel_requested, context, created_at}`.
`context` for `SAAS_CUSTOMER_RESEARCH` = `{software_idea: SoftwareIdea, opportunity?: Opportunity}`.

Lease: `AGENT_TASK_LEASE_SECONDS` (default 300). Heartbeat at least every lease/3. The SDK `AgentWorker` heartbeats every 60 s in a background thread. On `lease_lost` stop work immediately — another worker owns the task.
Max attempts: 3 (lease expiry or retryable fail each consume one).

### Result Bundle v1.0
`POST agent/tasks/{id}/results/` may be called many times per task (stream results in batches). Atomic per call.
```jsonc
{
  "schema_version": "1.0",           // required
  "evidence":       [{ "ref", "url", "title", "source_type", "excerpt", "retrieved_at", "metadata" }],
  "opportunities":  [{ "ref", "title", "problem_statement", "industry", "target_segment", "pain_severity", "score",
                       "competitors": [{ "name", "url", "notes" }], "market_signals": {}, "evidence_refs": [] }],
  "software_ideas": [{ "ref", "opportunity_ref", "name", "summary", "problem", "solution", "target_customers",
                       "key_features": [], "pricing_model", "differentiation", "risks": [], "mvp_scope", "score",
                       "evidence_refs": [], "submit_for_approval": false, "approval_summary": "" }],
  "businesses":     [{ "ref", "name", "website", "email", "phone",
                       "address": { "line1", "city", "region", "postal_code", "country_code" },
                       "latitude", "longitude", "category", "description", "source_data": {}, "evidence_refs": [] }],
  "leads":          [{ "ref", "business_ref" | "business_id", "status": "NEW|QUALIFIED|DISQUALIFIED", "score",
                       "qualification_notes", "problems": [Problem],
                       "contact": { "name", "role", "email", "phone",
                                    "email_type": "GENERIC_BUSINESS|PERSONAL_WORK|UNKNOWN",
                                    "legal_basis": "LEGITIMATE_INTEREST|CONSENT|UNKNOWN", "legal_basis_note" },
                       "evidence_refs": [] }],
  "project_briefs": [{ "ref", "lead_ref" | "lead_id", "title", "summary", "problems": [Problem], "proposed_solution",
                       "scope_items": [], "tech_stack": [], "estimated_effort_hours": { "min", "max" },
                       "estimated_budget": { "min", "max", "currency" }, "evidence_refs": [],
                       "submit_for_approval": false, "approval_summary": "" }],
  "campaigns":      [{ "ref", "name", "channel": "EMAIL",
                       "offer": { "headline", "value_proposition", "pricing", "call_to_action" },
                       "project_brief_ref" | "project_brief_id",          // LOCAL_LEAD_DISCOVERY only
                       "messages": [{ "lead_ref" | "lead_id", "subject", "body", "language", "sequence_step": 1 }],
                       "submit_for_approval": false, "approval_summary": "" }]
}
// Problem = { "code": "UPPER_SNAKE", "title", "severity": "LOW|MEDIUM|HIGH", "description", "evidence_refs": [] }
```
Rules
- `ref`: agent-chosen string ≤200, unique per (task, section). Refs resolve against this and earlier bundles of the **same task**. Cross-task links use `*_id` UUIDs.
- Allowed sections per task type: see agent contracts. Others → 400.
- Any unknown ref / invalid field → **400, nothing persisted**.
- Existing ref: updated if still editable (DRAFT/CHANGES_REQUESTED; Opportunity NEW; Lead NEW/QUALIFIED/DISQUALIFIED); evidence is immutable; otherwise listed in `skipped` with `reason: not_editable|immutable`.
- Businesses are deduplicated per workspace (domain, else name+city+country); blanks are filled, existing values kept.
- Messages: recipient = `contact.email` else business email. Skipped with `no_recipient` or `suppressed`. Body is **plain text without signature/opt-out** — the backend appends sender identity and unsubscribe footer. `sequence_step` must be 1 in v1.
- `submit_for_approval: true` creates a PENDING Approval after the bundle is persisted (no-op if already pending). Agents can never approve.
- Size: ≤500 items per section per call.

Result Report:
```json
{"created": {"evidence": 2, "software_ideas": 1}, "updated": {}, "skipped": [{"kind": "messages", "ref": "c1/l1/1", "reason": "suppressed"}],
 "refs": {"software_ideas": {"idea1": "<uuid>"}}, "approvals_requested": [{"target_type": "SOFTWARE_IDEA", "target_id": "<uuid>", "approval_id": "<uuid>", "status": "PENDING"}]}
```
Executable examples accepted by the backend test suite: `tests/support/bundles.py`.

## Change process
1. Change code + this file (+ agent contract) in one PR; regenerate `docs/openapi.yaml` (`python manage.py spectacular --file ../docs/openapi.yaml`) and `frontend/src/api/schema.d.ts` (`npm run gen:api`).
2. Add an entry to `INTEGRATION_STATUS.md › Contract changes` naming affected teams; breaking → also `DECISIONS.md`.
3. Run `pytest` (includes `tests/integration`).
